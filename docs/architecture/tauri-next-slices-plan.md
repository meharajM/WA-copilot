# Next Tauri migration slices

These slices advance the full-migration gates while retaining Electron as a transition fallback. The product UI target is a normal Windows browser; Tauri is native-capability host only. Each slice must be additive, authenticated, restart-safe, covered by tests, and must not claim full parity until browser product and data gates pass.

## Status — September 17, 2026

Windows is the primary release target. macOS bundle/smoke evidence below is useful for boundary validation only; each slice remains open until a Windows build, keychain, process-supervision, and user-flow check is recorded.

- Task 1 is implemented and independently reviewed clean: WhatsApp draft-only ingestion is durable, deduplicated, pause-aware, secret-redacted, and never sends through a provider.
- Task 2 is implemented and heavily hardened, but remains blocked from release use by the documented pathname TOCTOU limitation on platforms without descriptor-relative filesystem primitives, unresolved Windows no-follow support, and the final scalar-value secret-screening contract.
- Task 3 persistence is implemented and reviewed clean for the bounded seam: daemon session/message routes, restart durability, session isolation, idempotent message writes, and a typed Tauri host bridge.
- Task 4 generation is implemented for fixed OpenAI/OpenRouter endpoints as a bounded complete-response operation. It is not yet true streaming and provider cancellation is not yet propagated through `agentd`.
- Task 5/7/8/9 make LLM settings, credentials, WhatsApp transport settings, all three Cloud credential presence states, and daemon-backed chat reachable from the bounded native-capability diagnostics surface with visible failure states. Electron behavior remains unchanged.
- Browser product mounting is now explicit: normal browser loads pair with `agentd` and then mounts `App.tsx`; real Tauri loads only `NativeHostDiagnostics`. Browser text chat now ensures session/message ordering and generates through authenticated agentd, including CSRF rehydration after reload. The browser HTTP adapter covers exact remote LLM settings, durable product preferences, redacted audit logs/export, bounded text/image attachments with workspace metadata, OpenAI/OpenRouter credential presence/write/test, Bot Identity persistence, WhatsApp cloud settings/credential presence, bounded text and supervised document-to-Markdown Knowledge/Intelligence routes, and the first bounded memory graph/stats/export routes. Explicit browser WebGPU/WebLLM generation is now a local renderer path with user-initiated model download/cache management; it never moves model bytes or credentials through agentd. Electron remains the complete transition path for the full product while email, MCP, image/parser coverage, memory migration/backend switching, full attachment/file semantics and full WhatsApp flows remain unmigrated; browser Web Speech remains capability-gated and browser offline Vosk now uses the authenticated agentd model route.
- Browser autonomy now consumes authenticated `agentd` status, pause/resume and WhatsApp draft/outbox routes; explicit Autonomous Bot Mode sends through the same approved-draft state machine, while Response Permission remains review-only.
- Task 10/13 runtime seam and packaging are implemented: Tauri chat persistence now synchronizes and deletes sessions through authenticated `agentd` routes, and the packaged native host supervises a fixed, target-matched `agentd` runtime plus keyring helper. A fresh macOS bundle was manually smoke-tested through Ready status, session creation, and no-credential generation failure recovery. This is migration evidence, not a release-parity claim.
- Windows-first follow-up: the host now validates Windows process ownership/start identity, stages `.exe` resources, preserves the minimum Windows environment needed by Node/Credential Manager, and has a `build:tauri:win` CI entry point. Browser-shell fallback and packaged native smoke flows are verified; Windows native build, Credential Manager, signed NSIS install/upgrade, and resource-budget evidence still require a Windows runner.

## Task 1 — authenticated draft-only WhatsApp workflow

Extend the canonical HTTP `agentd/server.cjs` service with an authenticated, persisted WhatsApp draft workflow. The service must accept a normalized inbound WhatsApp event, deduplicate by provider event ID, honor the global pause state, create an immutable draft response record without sending through a real provider, and expose list/get/update-status operations for drafts. Drafts and their status must survive a daemon restart. Use strict payload limits and allow only the `whatsapp` channel and `draft`/`approved`/`rejected`/`sent` status transitions; this slice must never call a network channel provider. Add unit tests for authentication, deduplication, pause behavior, restart persistence, invalid transitions, and secret-free responses. Keep existing event endpoints compatible.

## Task 2 — data continuity manifest and preview/import engine

Add a host-neutral, non-secret migration utility that inventories known Electron stores and the current agentd stores, returns a deterministic preview with source path, target path, byte size, schema/version, and whether reauthentication is required, and imports only explicitly allowlisted non-secret JSON/SQLite stores into an isolated target directory. It must reject path traversal/symlink targets, refuse secrets, support dry-run and idempotent repeat import, create a recoverable backup before writes, and roll back on a failed store. Add fixture tests for clean import, repeat import, corruption, traversal, secret refusal, partial failure, and rollback. Do not delete or mutate the Electron source.

## Task 3 — Tauri session/chat vertical adapter

Add the first product-facing `agentd` session/chat API and typed browser client without replacing Electron. Persist sessions and messages in `agentd`, enforce per-session ownership, expose bounded create/list/send/history operations, and surface unavailable/restart-safe states in the browser UI. Keep native-only operations behind Tauri capability commands; the renderer must never receive credentials or arbitrary provider URLs. Add contract tests for session isolation, message ordering, bounded input, restart persistence and a no-credential fake generation path. Keep the existing `App.tsx` Electron path unchanged until the browser flow has equivalent evidence.
