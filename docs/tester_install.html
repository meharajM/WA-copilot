User Manual & Setup Guide

AIConsumerAgent v1.2 • Configuration & Lifecycle

1. The Application Interface

The sidebar of AIConsumerAgent provides access to several specialized views. Understanding the purpose of each "tab" is essential for effective testing.

QA Contract: For current pass/fail expectations, treat docs/app-behavior.md as the primary source of truth if this manual and the running app disagree.
📊
Command Center (Dashboard)
Your global overview. Monitor **Messages Per Day**, **Active Leads**, and the **Knowledge Doc Count**. Use the "Analysis" section to categorize customer intent via AI.
💬
All Chats (Conversations)
A unified stream of active sessions across channels such as WhatsApp and email. Select a chat to inspect the latest messages, agent output, and tool activity in the correct session.
👥
Lead Directory (CRM)
A CRM-lite view of contact-linked sessions. It surfaces session titles, contact identifiers, channel badges, timestamps, and status for quick triage, but it is not a full structured CRM extraction system.
🧠
Brain View (Advanced)
For technical audit of indexed knowledge. Use it to verify uploaded documents and other sources were ingested. Memory backend stats and the memory inspector live under Settings → Knowledge Base.
📨
Email Drafts
Review pending email drafts, escalations, and recent email send history. This is the main surface for human approval when email policy does not allow direct sending.

2. Windows Browser-First Runtime

For Windows users, the product workspace runs in Edge or Chrome. The small AICA native companion is used only for OS capabilities and local service lifecycle; it is not a second chat/settings application.

1
Start the companion: Launch the AICA native companion and wait for the local service to report ready.
2
Open the workspace: Choose Open browser workspace from the native diagnostics screen or tray menu.
3
Pair once: Enter the six-digit code shown by the explicit native Show pairing code action. The code expires, is single-use, and is not stored in the browser.
Native boundary: File/folder dialogs, credential presence, continuity staging and service diagnostics stay in the companion. Chat, channels, settings, Brain, memory and approvals stay in the browser tab. See docs/app-behavior.md for pass/fail behavior and known migration limits.

3. Connecting the AI (OpenRouter Guide)

To enable the agent's "Brain," you must connect an LLM Provider. We recommend OpenRouter for access to top-tier models like GPT-4o or Claude 3.5 Sonnet.

1
Generate API Key: Visit openrouter.ai/keys, sign in, and create a new key. Copy it securely.
2
Access Settings: Click the **Gear Icon** in the bottom-left sidebar of the AIConsumerAgent app.
3
Provider Choice: Navigate to the **AI Model Connection** section and select **OpenRouter** from the pill row.
4
Link & Select: Paste your API Key. The app will fetch available models. Choose openai/gpt-4o or your preferred model.
🔑 Important: If the "Test Connection & Fetch Models" button fails, ensure your OpenRouter account has available credits, because the app performs a small health check on connection.

4. App Usage Lifecycle Flow

This flowchart summarizes the onboarding journey from first install to autonomous business support.

1️⃣
Local pairing: Pair the Edge/Chrome workspace with the six-digit code from the native companion.
2️⃣
Doc Training: Upload bounded text/Markdown/CSV/JSON/XML/HTML/log content in the browser "Train AI" section. Binary conversion remains a native migration gate.
3️⃣
Persona Tuning: Set "Tone" and "Assistant Name" in Identity Settings.
4️⃣
Go Live: In the browser workspace, enable Response Permission only for explicit text sends and approved drafts. Autonomous Bot Mode is intentionally disabled in browser mode; it remains an Electron transition-client capability until the supervised agentd response-policy path is migrated.
5️⃣
Supervision: Reply to bot escalations on your phone to resolve complex cases.
